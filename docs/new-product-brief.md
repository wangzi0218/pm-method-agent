# 新产品启动 Brief

> 文档状态：新项目启动建议。用于从 `PM Method Agent` 的探索成果出发，设计一个更简洁、面向产品经理个人或团队提效的新产品。

## 一句话方向

新项目可以先定义为：

`一个面向产品经理的工作流 harness，用来把想法、反馈、需求草稿和团队上下文，组织成可持续推进的产品判断过程。`

它不必一开始就是完整 agent 平台。

更好的第一版目标是：

`让产品经理少重复解释背景，少在模糊需求里来回打转，更快知道下一步该补什么、该找谁、该不该继续。`

## 和 PM Method Agent 的关系

`PM Method Agent` 是探索型内核。

新项目应该是产品化重构。

建议复用：

- workspace / case / memory 的抽象。
- query loop 和事件账本思路。
- 方法关口：问题定义、决策挑战、验证设计。
- 记忆写入必须可见、可确认、可撤回。
- runtime 负责控制，LLM 负责理解和表达增强。

建议不要直接复用：

- 过重的文档体系。
- 过多候选入口。
- 复杂网页 demo 结构。
- 一开始就支持 MCP、IDE、网页、CLI、sub-agent 的全形态。

## 新项目更适合的最小范围

第一版建议只选一个主入口。

候选入口：

1. 文档/聊天式工作台
2. 浏览器本地网页
3. IDE / agent skill
4. issue / ticket 辅助工具

如果目标是产品经理个人或小团队提效，我建议第一版选：

`轻量网页工作台 + 可被 agent/skill 调用的本地服务。`

原因：

- 产品经理更容易理解网页入口。
- 团队演示和反馈成本低。
- 后续可以自然接 skill / MCP。
- 不会一开始被 IDE 宿主差异绑住。

但网页必须克制，不能做成复杂后台。

## 第一版核心对象

建议只保留 5 个对象：

### 1. Workspace

代表一个项目、团队、产品线或个人工作区。

它负责保存：

- 项目背景
- 稳定约束
- 常用指标
- 用户偏好
- 最近案例

### 2. Case

代表一个产品问题或需求草稿。

它负责保存：

- 原始输入
- 多轮补充
- 当前阶段
- 当前卡点
- 下一步建议
- 结论或暂缓原因

### 3. Memory

代表可复用背景。

它必须区分：

- 项目背景
- 用户偏好
- 当前案例临时信息
- 团队规则

### 4. Loop

代表每轮用户输入如何被承接。

它负责区分：

- 新问题
- 继续补充
- 项目背景更新
- 查看历史
- 下一步建议
- 明确暂缓或继续

### 5. Card

代表用户每轮看到的结果。

第一版卡片只需要回答：

- 我现在怎么理解？
- 卡在哪里？
- 下一步最该补什么？
- 是否应该先停？

## 第一版不做什么

建议明确不做：

- 不做完整 PRD 生成。
- 不做团队权限和组织后台。
- 不做复杂项目管理系统。
- 不做无限聊天机器人。
- 不做多 agent 编排。
- 不默认把所有信息写进长期记忆。
- 不把所有方法论都做成表单。

## 第一版用户路径

建议从这条路径开始：

1. 用户创建或选择一个工作区。
2. 用户输入一句草稿、反馈或指标异常。
3. 系统判断这是新 case、继续 case，还是项目背景。
4. 系统输出一张轻卡片。
5. 用户继续自然补充。
6. 系统只追最影响推进的一两个点。
7. 系统在合适时给出暂缓、继续验证或进入方案的建议。
8. 如果用户提供稳定背景，系统提示是否记住。

## 第一版成功标准

不建议用“生成了多少内容”衡量。

更适合看：

- 用户是否少重复解释背景。
- 用户是否更快知道下一步该补什么。
- 系统是否能挡住过早方案化。
- 系统是否能处理半步回答。
- 系统是否能在用户说“不急、不值得做”时停下来。
- 用户是否愿意把真实草稿丢进去，而不是只用 demo 样例。

## 技术架构建议

可以借鉴 harness 思路，把系统拆成几层：

### 1. Runtime Layer

负责：

- query loop
- turn count
- active case
- memory reference
- event log
- execution ledger
- terminal state

### 2. Method Layer

负责：

- 问题定义
- 决策挑战
- 验证设计
- 阶段关口
- 停止条件

### 3. Memory Layer

负责：

- 项目背景
- 用户偏好
- 团队规则
- 当前案例临时事实
- 写入确认和撤回

### 4. LLM Layer

负责：

- 语义理解
- 角色和场景抽取
- 文案自然化
- 草稿归一化

不负责：

- 最终权限决策
- 静默写入记忆
- 绕过阶段机

### 5. Interface Layer

负责：

- 网页
- CLI
- skill
- MCP

但第一版只选一个主入口。

## 新项目的第一周建议

如果要开新仓库，第一周不要急着写完整功能。

建议交付：

1. 一页产品定义。
2. 一份对象模型。
3. 一条端到端用户路径。
4. 5 个真实样本。
5. 一个最小可运行原型。

第一周先证明：

`用户输入一个真实草稿，系统能承接、追问、记住背景，并给出下一步。`

做到这一步，再考虑扩展入口和团队协作。
