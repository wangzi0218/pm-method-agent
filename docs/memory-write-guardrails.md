# 记忆写入与防线设计

## 为什么要单独设计

`PM Method Agent` 需要记住用户已经说过的项目背景、协作偏好和案例补充，否则用户每次都要重新交代上下文，产品会退回普通问答体验。

但记忆也不能变成静默写入。只要某条记忆会影响后续判断，就必须让用户看得见、改得掉、必要时能撤回。

这一层的目标不是做一个复杂的知识库，而是让记忆像自然对话一样顺手沉淀，同时保留足够的防线。

## 核心原则

### 1. 先承接，再确认

用户自然说出背景时，系统可以先在当前轮次里承接使用，不要立刻打断用户。

例如：

- “我们是 ToB 的 HIS 产品，主要在网页端用。”
- “我们团队一般先看履约率和到诊率。”
- “我希望你先说结论，不要写太长。”

这些内容可以先参与当前判断，但是否进入长期记忆，要按风险等级处理。

### 2. 记忆分层，不混在一起

记忆至少分成三层：

- `当前案例`：只对这次分析有效，例如当前频率、现状流程、这轮判断倾向。
- `项目背景`：后续同一项目会反复使用，例如产品类型、平台、角色结构、稳定约束、常看指标。
- `个人偏好`：用户稳定协作偏好，例如希望更简洁、先给结论、偏中文表达。

同一句话可能同时包含多层信息，但写入时必须拆开，不要整句塞进长期记忆。

### 3. 风险越高，确认越显式

不是所有记忆都需要同样强的确认。

低风险记忆可以自然沉淀，高风险记忆必须显式确认。

### 4. 记忆必须可见

只要系统在后续判断里引用了某条长期记忆，就应该在合适的位置轻量提示。

例如：

- “我先沿用「诊所工作台」的项目背景。”
- “这轮先按企业产品 / 网页端 / 前台与店长这个背景看。”
- “如果不是同一个项目，直接说一声，我会改按新背景看。”

### 5. 用户纠正优先级最高

当用户说“不是这个项目”“刚才说错了”“这个只针对这次”“不要记住”时，纠正必须优先于原有记忆。

这类语句不应该被当作普通补充，而应该进入记忆修正流程。

## 写入风险等级

### L0：不写入

适合：闲聊、情绪、一次性表达、没有可复用价值的信息。

处理方式：不生成记忆建议。

### L1：只写入当前案例

适合：当前频率、现状流程、失败案例、当前判断倾向。

处理方式：可以自然写入当前案例，不需要额外确认。

示例：

- “一周大概 20 单会晚核销。”
- “现在主要靠前台手工翻列表提醒。”
- “这轮我先不急着产品化。”

### L2：建议写入项目背景

适合：产品类型、主要平台、角色结构、长期约束、常看指标。

处理方式：当前轮次可以先承接，但长期写入前要给轻量确认。

示例：

- “这个项目是 ToB 的 HIS 产品，主要在网页端使用。”
- “店长通常对结果负责，前台是主要操作人。”
- “我们团队一般先看履约率和到诊率。”

推荐交互：

> 这句看起来会反复用到，要不要记进项目背景？

可选动作：

- 记住
- 只用于这次
- 先不记

### L3：建议写入个人偏好

适合：输出风格、语言、分析侧重点、协作习惯。

处理方式：必须轻量确认，避免系统误解用户短期要求。

示例：

- “以后你先说结论。”
- “我希望卡片短一点，不要太正式。”
- “我更关注 ToB 场景里的组织流程。”

推荐交互：

> 这更像你的协作偏好，要不要以后默认按这个来？

可选动作：

- 以后默认这样
- 只这次这样
- 不记

### L4：敏感或高影响记忆

适合：组织规则、合规约束、强决策偏好、可能影响资源投入判断的信息。

处理方式：必须显式确认，并保留变更记录。

示例：

- “所有需求默认先不做，除非老板点名。”
- “我们不考虑非产品路径。”
- “合规要求不允许保存某类数据。”

推荐交互：

> 这条会明显影响后续判断，我需要你确认后再记住。

可选动作：

- 确认记住
- 改成当前案例备注
- 不记

## 默认行为

### 当前阶段建议采用的策略

短期最适合采用 `建议写入 + 用户确认` 的混合策略。

默认规则：

- 当前案例记忆：自动写入。
- 项目背景：先承接当前轮，生成写入建议，用户确认后再长期保存。
- 个人偏好：先承接当前轮，用户确认后再长期保存。
- 高影响规则：不自动写入，必须确认。

这样既不会频繁打断自然对话，也不会让长期记忆悄悄改变系统行为。

## 交互形态

### 网页

网页里不建议弹窗打断。

更合适的形态是侧栏或卡片底部的轻量确认条：

```text
这句可能值得记住

项目背景：这个项目是 ToB 的 HIS 产品，主要在网页端使用。

[记住] [只用于这次] [不记]
```

用户不处理时，不应阻塞主分析流程。

### CLI

CLI 不适合做复杂交互，短期可以先输出建议：

```text
这句先怎么记
- 项目背景：更像后面会反复用到的前提。可以输入“记住项目背景”来保存。
```

后续再补命令式确认。

### Agent / Skill

Agent 入口更适合自然语言确认：

- “记住这个项目背景”
- “这句只针对这次”
- “不要记住我的偏好”
- “刚才那个背景说错了，改成移动端为主”

## 运行时职责边界

### Runtime 负责

- 记忆分层
- 写入风险等级
- 是否需要确认
- 写入账本
- 可撤回和可覆盖
- 后续引用时可见化

### LLM 负责

- 判断自然语言中有哪些可记忆片段
- 帮助拆分一句话里的项目背景、案例信息和个人偏好
- 生成更自然的确认文案

### LLM 不负责

- 直接决定长期写入
- 绕过确认策略
- 维护最终记忆状态
- 决定记忆优先级

## 最小落地路径

### 第一步：确认条只做展示

沿用现有 `memory_write_suggestions`，在网页和 CLI 中明确展示：

- 建议写入目标
- 建议原因
- 来源片段
- 当前是否已经写入

这一阶段不自动写长期记忆。

### 第二步：补确认动作

为建议增加动作：

- `accept-memory-suggestion`
- `use-once`
- `dismiss-memory-suggestion`

确认后再调用项目背景或用户偏好写入能力。

### 第三步：补撤回和改写

支持：

- “刚才那条不要记了”
- “把项目背景改成移动端为主”
- “这个偏好只对这个项目有效”

当前最小实现已经先落在网页工作区侧栏里：

- 已记住的项目背景和个人偏好会按字段展示，而不是只显示一段摘要。
- 单值字段支持轻量改写，例如项目名、产品类型、主要平台、业务领域、输出风格。
- 多值字段支持单条删除，例如关键角色、稳定约束、关注指标、常见约束。
- 用户可以选择“不用这个项目”，让后续分析先停止沿用当前项目背景。

这部分参考 OpenWebUI 的记忆管理思路：记忆可以由系统建议，但长期保留、修改和删除要交还给用户。短期不做完整设置中心，先把最常用的查看、改写和删除放在工作区上下文里。

### 第四步：引用可见化

在后续卡片里展示：

- 本轮沿用了哪个项目背景
- 哪些字段来自项目背景
- 哪些字段来自用户本轮输入

当前最小实现会在 `case_runtime.memory_references` 中暴露引用信息，并在网页摘要区显示“这轮沿用了”：

- 项目背景引用会展示项目名和被带入的关键字段，例如产品类型、主要平台、业务领域、关键角色。
- 个人偏好引用会展示本轮默认采用的输出风格、语言偏好和判断习惯。
- 如果用户发现不是同一个项目，可以直接点“不是这个项目”，系统会停止沿用当前项目背景。

这里仍然保持轻量提示，不把用户带进复杂设置页；真正的记忆改写和删除仍然在工作区记忆区完成。

## 成功标准

这一层做好后，用户应该能感受到：

- 不用每次重复补项目背景。
- 系统不会偷偷长期记住一句话。
- 系统记住的东西自己看得见。
- 记错了可以自然纠正。
- 当前案例、项目背景、个人偏好不会混在一起。
