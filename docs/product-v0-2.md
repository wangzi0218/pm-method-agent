# v0.2 产品定义

`v0.2` 的目标不是增加更多分析模块，而是让 `PM Method Agent` 更像一个能连续协作的产品判断助手。

这一版重点解决：

`用户只有一句模糊草稿时，系统能不能接住、追问、承接补充，并把问题推进到可判断的状态。`

## 一句话定位

`v0.2` 是多轮协作与记忆闭环预览版。

它应该让用户感受到：

- 不用先写完整需求
- 可以边聊边补背景
- 系统知道当前卡在哪一步
- 项目背景和偏好不会每次都重新问
- 长期记忆会先让用户确认

## 面向谁

优先面向：

- 中初级产品经理：有问题草稿，但不知道下一步补什么
- 独立负责需求判断的人：需要快速判断值不值得做
- 习惯和 AI 协作的人：不想每次都手写结构化提示词

暂时不优先面向：

- 只想生成完整 PRD 的人
- 只需要项目管理和排期拆解的人
- 需要团队级协作后台的人

## 核心场景

### 1. 模糊草稿进入

用户可能只说：

```text
前台最近老是漏提醒患者，我在想是不是要处理一下。
```

系统应该先判断缺什么，而不是直接进入方案。

### 2. 连续补充推进

用户继续补：

```text
这是一个 ToB 医疗服务平台，主要通过网页端使用，前台在操作，店长会看结果。
```

系统应该承接上一轮，而不是让用户重新说完整上下文。

### 3. 决策倾向出现

用户可能说：

```text
这个需求客户有反馈，但我感觉不像强痛点，研发资源也比较紧张。
```

系统应该把这句话承接成决策关口，允许继续产品化、先看非产品路径或暂缓。

## 这一版必须做好什么

### 连续追问

- 一次只问最影响推进的 1 到 3 个问题
- 用户只回答一半时，也要承接已回答部分
- 不要为了追求完整信息而反复打断

### 阶段推进

- 场景信息不足时，先补场景
- 问题定义不清时，先拆现象、解释和方案
- 到了决策关口时，要停下来让人选择
- 可以进入验证设计时，再谈指标、护栏和停止条件

### 记忆闭环

- 当前案例信息、项目背景和长期偏好要区分
- 系统可以建议记住信息
- 长期记忆必须让用户确认
- 用户能看到这一轮沿用了哪些记忆
- 用户能撤回或改掉错误记忆

### 入口一致

- CLI、统一 agent、本地 HTTP 服务和网页演示应使用同一套方法内核
- 不同入口对同一段对话应给出相近推进结果
- 外壳只负责展示和交互，不重新实现方法判断

## 当前已经具备

- CLI、统一 agent、本地 HTTP 服务和网页演示
- 工作区、案例和历史消息
- 连续追问选择、回答承接和阶段转场提示
- 记忆建议、用户确认、记忆管理和记忆引用展示
- 兼容 OpenAI 接口格式的模型适配骨架，以及本地规则回退
- 基础回归、真实问题试跑文档和网页验收脚本

## 当前不承诺

- 完整云端多用户服务
- 正式 MCP 外壳
- 正式 IDE 插件或 skill 包
- sub-agent 编排
- 完整 PRD 生成
- 大而全的网页后台

## 怎么判断 v0.2 做得好不好

体验上应满足：

- 用户给一句模糊草稿，系统能接住
- 连续补 2 到 4 轮，不需要重写上下文
- 用户知道当前卡在哪、为什么卡、补完会去哪

方法上应满足：

- 不会默认顺着方案走
- 不会因为多轮补充乱跳阶段
- 不会为了信息完整而过度追问
- 到决策关口时会停下来

产品上应满足：

- 网页演示比命令行更容易上手
- 记忆建议不会静默写入
- 用户能看见系统这一轮怎样承接了上下文

## 下一步

`v0.2` 封装完成后，更适合继续做三件事：

- 扩真实问题回归样本
- 继续收敛网页演示的轻量体验
- 再评估 MCP、IDE skill 和 sub-agent 是否进入下一版本

发布检查见 [v0.2 发布准备清单](v0-2-readiness.md)。
