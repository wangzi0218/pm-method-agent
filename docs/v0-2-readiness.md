# v0.2 发布准备清单

## 版本定位

`v0.2` 是“多轮协作与记忆闭环预览版”。

它的重点不是把系统包装成成熟 SaaS，也不是宣布已经具备完整多代理能力，而是把 `PM Method Agent` 从“能输出审查卡的本地方法内核”，推进到“能承接几轮真实产品思考的本地 agent 内核”。

更具体地说，`v0.2` 应该让用户看到：

- 可以从一句模糊草稿开始
- 可以跨轮补充背景、证据和决策倾向
- 系统知道当前卡在哪一关
- 系统能说明这一轮沿用了哪些项目背景或偏好
- 需要长期记住的信息会先让用户确认

## 当前已具备

发布 `v0.2` 前，当前仓库已经具备这些基础能力：

- CLI、统一 agent 入口、本地 HTTP 服务和最小网页 demo
- 工作区、案例、历史消息和 runtime session
- 连续追问选择、回答承接和阶段转场提示
- 记忆建议、用户确认、记忆管理和记忆引用展示
- OpenAI-compatible 的 LLM 适配骨架，并保留本地规则回退
- runtime 事件摘要、恢复建议、执行账本和开放事项摘要
- 真实问题试跑文档、人工冒烟文档和自动化 smoke tests

## 明确不承诺

`v0.2` 仍然是预览版，不承诺下面这些能力已经成熟：

- 不承诺完整 MCP 外壳
- 不承诺 IDE 插件或 skill 包已经正式发布
- 不承诺 sub-agent 编排已经可用
- 不承诺云端多用户协作和权限体系
- 不承诺网页 demo 是完整后台或完整产品工作台
- 不承诺能直接生成完整 PRD
- 不承诺模型增强永远可用，模型不可用时仍以本地方法内核为准

## 发布前必须通过的检查

发布前至少检查这些项：

- README 能说明当前入口、能力边界和快速体验方式
- `docs/product-v0-2.md` 与实现状态一致，没有把已完成能力写成待办
- `docs/implementation-roadmap.md` 能说明当前已经走到第四阶段后段
- `docs/release-process.md` 同时覆盖历史 `v0.1.0` 和当前 `v0.2` 准备方式
- 用户可见文案没有明显中英混杂和内部工程术语外露
- 仓库内没有真实 API key、临时调试文件或只对作者有意义的说明
- 自动化测试和网页验收脚本通过

## 推荐验收命令

基础回归：

```bash
PYTHONPATH=src python3 -m unittest tests.test_smoke tests.test_human_like_flows
```

网页 demo 验收：

```bash
PMMA_WEB_ACCEPT_PORT=8020 bash scripts/web_demo_acceptance.sh
```

如果要检查完整测试集，可以再执行：

```bash
PYTHONPATH=src python3 -m unittest discover -s tests
```

## 建议打标签条件

只有同时满足下面条件后，才建议打 `v0.2.0` 标签：

- 上面的推荐验收命令已经通过
- README 和文档索引已经指向 `v0.2` 准备清单
- 发布说明能清楚说明“预览版”边界
- 使用者能在本地跑通 CLI 或网页 demo
- 你确认这次要作为一个明确版本对外固定下来

如果只是完成文档和封装准备，建议先 commit / push，不急着打 tag。

## 下一步建议

`v0.2` 准备完成后，后续更适合沿着三条线继续：

- 继续补真实问题回归样本，减少长尾场景误判
- 继续收敛网页 demo 的轻量体验，不把它做成复杂后台
- 再评估 MCP、IDE skill 和 sub-agent 编排是否进入下一个版本
