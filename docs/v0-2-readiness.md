# v0.2 发布准备清单

这份清单用来判断：现在是否可以把项目固定成 `v0.2.0`。

结论先说：`v0.2` 可以作为“多轮协作与记忆闭环预览版”准备发布，但不应该被描述成完整平台。

## 版本定位

`v0.2` 是一个本地可运行的产品判断 agent 预览版。

它证明的不是“系统已经成熟”，而是：

- 模糊草稿可以被接住
- 多轮补充可以被承接
- 阶段和决策关口可以被控制
- 记忆建议可以被用户看见和确认
- CLI、网页演示和服务层可以共用同一套方法内核

## 已具备能力

面向使用者：

- 从一句自然语言草稿开始
- 多轮补充场景、证据、角色和决策倾向
- 输出轻量审查卡
- 网页里查看当前卡片、历史、案例和记忆建议
- 用户确认后再写入长期记忆

面向开发者：

- CLI、统一 agent、本地 HTTP 服务和网页演示
- 工作区、案例、历史消息和运行时状态
- 兼容 OpenAI 接口格式的模型适配骨架
- 本地规则回退链路
- 基础单元测试和网页验收脚本

## 明确不承诺

`v0.2` 不承诺这些能力已经成熟：

- 完整云端多用户服务
- 注册登录、权限和团队协作后台
- 正式 MCP 外壳
- 正式 IDE 插件或 skill 包
- sub-agent 编排
- 完整 PRD 自动生成
- 通用 AI 聊天产品

## 发布前必须检查

### 产品和文档

- README 能让产品经理快速理解项目价值
- 快速开始能跑通第一轮体验
- 文档索引能按读者分流
- `v0.2` 边界没有过度承诺
- 用户可见文案没有明显中英混杂

### 功能和体验

- 模糊草稿能触发场景补充或问题定义
- 用户补一轮背景后，系统能承接当前案例
- 决策倾向能进入关口或暂缓语义
- 记忆建议不会静默写入
- 网页演示能完成输入、补充、切案例和查看记忆

### 工程和发布

- 测试通过
- 网页验收通过
- 仓库没有真实密钥
- 发布说明草稿已准备
- tag 前已经确认版本号和发布口径

## 推荐验收命令

基础回归：

```bash
PYTHONPATH=src python3 -m unittest tests.test_smoke tests.test_human_like_flows
```

网页验收：

```bash
bash scripts/web_demo_acceptance.sh
```

如果要跑完整测试集：

```bash
PYTHONPATH=src python3 -m unittest discover -s tests
```

## 什么时候可以打 tag

建议只有满足这些条件后再打 `v0.2.0`：

- 上面的验收命令通过
- README 和 P0 用户文档已经完成一轮产品经理视角优化
- `docs/releases/v0.2.0.md` 已经和当前能力一致
- 你确认这版要作为明确版本对外固定

如果只是完成封装准备，先 commit / push 即可，不急着打 tag。
